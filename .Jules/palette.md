## 2024-06-04 - Nesting Interactive Elements inside Clickable Containers
**Learning:** When a generic container element (like a card `<div>`) acts as the primary clickable navigation point, adding nested interactive elements (like Wishlist or "Buy now" buttons) inside it causes event bubbling. This means clicking the button also triggers the card's navigation, leading to unexpected behavior. Furthermore, adding `role="button"` to the outer `div` to make it accessible while it contains other buttons is a severe WCAG accessibility violation.
**Action:** When designing clickable cards with inner actions, always use `onClick={(e) => e.stopPropagation()}` on the nested buttons to prevent triggering the parent container's click events. Avoid adding `role="button"` or `tabIndex` to the parent container if it contains other focusable interactive elements; instead, ensure nested interactive elements are fully keyboard accessible with appropriate focus states (e.g., `focus-visible:ring-2`) and ARIA labels.
